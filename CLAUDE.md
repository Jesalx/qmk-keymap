# QMK keymap for the ZSA Voyager

QMK external userspace. `jesal.c` is included by `keymaps/jesal/keymap.c`; third-party code is vendored as community modules in `modules/`.

## Commands

- Build: `qmk compile -kb zsa/voyager -km jesal`
- Lint: `task qmk-lint` (`qmk lint`; needs a comment as the first line of each keymap C/H file). `task check` runs all CI lints.
- Format: `task format` (clang-format via `qmk format-c`, using the repo `.clang-format` copied from QMK); `task format-check` is the CI check. The `os_shortcut` table in `jesal.c` is wrapped in `// clang-format off` to stay one row per key.
- Tools: `flake.nix` is the dev shell, entered automatically by direnv (`.envrc`, run `direnv allow` once) or manually with `nix develop` / `nix develop -c task <name>`; every `task` target expects its tools on `PATH` and does not call `nix-shell` itself. In this jj-colocated repo, new flake files are invisible to `nix` until committed, so use `nix develop path:.` meanwhile. `flake.lock` pins nixpkgs, and CI runs its lint, format and generated-file steps inside the same dev shell (Nix installed with `DeterminateSystems/nix-installer-action`, store cached by `DeterminateSystems/magic-nix-cache-action`), so local and CI tool versions are identical. Update them with `nix flake update`.
- Flash: `task flash` (`qmk flash`; needs `dfu-util`, provided by the dev shell)
- Regenerate `zsa_voyager_jesal.json`, `keymap.svg` and the README leader table: `task`

## Conventions

- `keyboards/zsa/voyager/keymaps/jesal/keymap.c` is the only hand-edited keymap. The JSON and SVG are generated by `task`; rerun it after changing layers and commit the results.
- The left thumb key (`LEADER_GUI` in `jesal.c`) is tap = Super Leader, hold = GUI. Sequences live in `keymaps/jesal/super_leader.def`; each needs a trailing `// description`, which `tools/leader_table.sh` turns into the README table (between the `leader:start`/`leader:end` markers). The module is vendored (Apache-2.0, from `getreuer/qmk-modules`) in `modules/getreuer/super_leader` and enabled via the keymap's `keymap.json`.
- `socd_cleaner` and `palettefx` are vendored the same way in `modules/getreuer/`. Module RGB effects are named `RGB_MATRIX_COMMUNITY_MODULE_<NAME>`, and `SOCDTOG` comes from the SOCD module.
- QMK is built from upstream `qmk/qmk_firmware` master (`user.qmk_home`), not pinned.
- Releases are automatic: a push to `main` that changes `qmk.json`, `keyboards/`, `modules/` or any `*.c`/`*.h` and passes CI publishes a GitHub release tagged `vYYYY.MM.DD-<sha>` with the firmware `.bin` and generated notes (the `release` job in `build.yaml`). Changes outside those paths do not release.
- CI (`.github/workflows/build.yaml`) builds the `qmk.json` target, runs `nix flake check`, `qmk lint`, a clang-format check, `actionlint` (locally: `task check`), and fails if `zsa_voyager_jesal.json` `keymap.svg` or `README.md` differ from what `task` regenerates.
